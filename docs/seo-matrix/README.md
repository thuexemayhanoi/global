# SEO A–Z Matrix (working state on GitHub)

This folder is the programme's state. Anyone (owner, ChatGPT, a new Claude session) can read it on `main` and know what was done, what is in progress and what comes next. Nothing here depends on a chat session.

| File | What it holds |
|---|---|
| `TASKS.json` | The task board, maintained by hand: one entry per task with phase, scope (Matrix ids), status, branch, merge commit, PR, deploy run, live-QA runs, evidence and `next_action`. |
| `CHECKPOINT.json` / `CHECKPOINT.md` | The resume point: the current task and its next action, the next TODO tasks, status counts. |
| `MASTER-SEO-MATRIX.csv` | One row per published URL: language, primary query, intent, title and description (length, estimated SERP width, check), H1, heading counts, content depth, FAQ, internal links, featured image and og:image, technical issues, per-phase task and status, and `next_action`. |
| `IMAGE-SEO-MATRIX.csv` | One row per image use (and one `NO_IMAGE` row per Hub/Supporting URL still without a cover): file, format, pixel size, bytes, 100–300 KB check, alt and its check, srcset/sizes, width/height, loading, task, status. |
| `CONTENT-SEO-MATRIX.csv` | One row per Pillar, Hub and Supporting URL: depth, floor, check, headings, FAQ, references, internal links, graph action, task, status. |
| `TASK-BOARD.csv` | Earlier batches A–Y (from `docs/seo-audit/execution/batches.json`) plus the tasks of `TASKS.json`, flattened. |

All files except `TASKS.json` and this README are generated by `python3 docs/seo-audit/tools/az_matrix.py` (`--check` reports stale files). The 16-sheet Excel workbook `reports/seo/GLOBAL-SEO-AZ-MASTER-MATRIX.xlsx` carries the same data in the sheets IMAGE SEO MATRIX, CONTENT SEO MATRIX and SEO TASK BOARD.

## Statuses

`TODO` → `IN_PROGRESS` (work on a branch) → `FIXED` (committed on a PR branch, local QA passed) → `MERGED` (merge commit on `main`) → `DEPLOYED` (GitHub Pages run succeeded) → `LIVE_VERIFIED` (live markup QA and post-publish QA passed on the deployed commit). `BLOCKED` needs someone outside the repository. Per-URL dimensions also use `OK` (no change needed), `NOT_FORCED` (rule does not apply, e.g. no word floor for legal pages) and `NOT_NEEDED`.

A PR records its own task as `FIXED`. The next PR (or a ledger-sync PR) adds the merge commit, deploy run and live-QA runs, which move the task to `LIVE_VERIFIED`. A task is never marked done without those run ids.

## Order of work

Finish open work → push Matrix → image SEO (`IMG-*`, max 100 images per batch) → titles and descriptions (`META-*`) → content upgrade (`CONTENT-*`) → technical SEO (`TECH-*`); each batch: QA → PR → merge → deploy → live verification → Matrix sync.

## Standards used by the checks

- **Images**: main image 100–300 KB, WebP; smaller files accepted when sharp (never padded); responsive variants are smaller by design; anything over 300 KB is re-encoded or the reason is recorded. Alt text in the page language, explicit width/height, `srcset`, lazy loading below the fold. Covers are built only from the page's own H1 and section headings over the site's existing topic illustration; no stock or invented photos.
- **Titles**: fit about 600 px in Google results (≈50–65 Latin characters, ≈30 CJK characters). Short titles are reviewed and lengthened only when a natural, accurate wording exists; a good title is never padded.
- **Descriptions**: 140–160 characters for Latin-script languages, 60–120 characters for zh, ja and ko.
- **Content floor** (≈1,000 English words): Latin words < 1,000, Korean words < 750, Chinese/Japanese characters < 1,500. Pages below it are expanded toward 1,600+ words only where the topic and reliable sources support it. Legal, contact and navigation pages have no floor.

## Resume ("tiếp tục")

1. Read `CHECKPOINT.json` and `TASKS.json` on `main`.
2. Check the current task's branch, PR, CI, deploy and live QA.
3. Finish it; if it is done, take the first `next_todo`.
4. Regenerate the Matrix, push, and leave a new checkpoint before stopping.

Owner-only items (Search Console, analytics, backlinks, keyword volumes, business data) are listed in `docs/seo-audit/OWNER-ACTIONS.md` and never block this work. Rankings and indexing are not measured here.
